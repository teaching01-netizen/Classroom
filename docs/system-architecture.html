QR Command Center

System Architecture Overview - Attendance Management Platform

High-Level System Architecture

The QR Command Center is a real-time attendance management system that generates QR codes for classroom check-ins, tracks student attendance across sessions and courses, and provides teachers with dashboards to monitor engagement.

Room State Machine

Each room follows a strict state machine for QR code lifecycle management. The state transitions are validated and persisted to ensure consistency. 

stateDiagram-v2
    [*] --> Idle: Create Room
    
    Idle --> Running: Start Room
    Idle --> Stopped: Delete Room
    
    Running --> Fetching: Fetch QR Code
    Running --> Stopped: Stop Room
    
    Fetching --> Running: Success
    Fetching --> Warning: Rate Limited / Auth Conflict
    Fetching --> AuthExpired: Session Expired
    Fetching --> Stopped: Invalid Payload
    
    Warning --> Fetching: Retry
    Warning --> Stopped: Stop Room
    
    AuthExpired --> Fetching: Retry with Fresh Auth
    AuthExpired --> Stopped: Stop Room
    
    Stopped --> Running: Restart
    
    note right of Idle: Waiting to start
    note right of Running: QR code active
    note right of Fetching: Request in progress
    note right of Warning: Recoverable error
    note right of AuthExpired: Needs re-login
    note right of Stopped: Terminal state

QR Code Generation Flow

The system continuously fetches fresh QR codes from Warwick before they expire. The RoomManager runs a worker goroutine per room with automatic recovery. 

sequenceDiagram
    participant UI as Frontend
    participant API as Go API
    participant RM as RoomManager
    participant Pool as SessionPool
    participant Warwick as Warwick API
    participant DB as PostgreSQL
    
    UI->>API: POST /api/rooms/{id}/start
    API->>RM: StartRoom(roomID)
    RM->>RM: Create worker goroutine
    RM->>DB: Persist Running state
    RM-->>UI: WebSocket: RoomUpdated
    
    loop Every 500ms-1.5s
        RM->>RM: Check QR expiration
        alt QR expired or about to expire
            RM->>RM: TransitionTo(Fetching)
            RM-->>UI: WebSocket: RoomUpdated
            RM->>Pool: Acquire session
            Pool-->>RM: Session cookie
            RM->>Warwick: POST /GetQRCode
            Warwick-->>RM: QR URL + TTL
            RM->>RM: TransitionTo(Running)
            RM->>DB: Persist QR data
            RM-->>UI: WebSocket: RoomUpdated
        end
    end
    
    Note over UI,DB: Frontend receives real-time updates via WebSocket

Technology Stack

Go 1.21+ Chi Router PostgreSQL pgx Pool React 18 Zustand WebSocket Vite Mermaid Docker Railway
1

Session Pool

Manages multiple Warwick auth sessions for parallel QR fetching with automatic rotation and conflict detection.

2

Room Manager

Orchestrates QR code lifecycle with goroutine-per-room workers, exponential backoff, and WebSocket broadcasting.

3

Data Refresher

Background job that periodically fetches course data to warm the cache and ensure fresh data availability.

4

Report Prewarmer

Pre-computes attendance reports and persists them to PostgreSQL for fast dashboard loading.
